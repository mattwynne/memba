---
title: "OpenRouter"
description: "Route Fabro model reviews through OpenRouter"
---

OpenRouter is an OpenAI-compatible gateway. Configure it in the Fabro server’s
`~/.fabro/settings.toml`, then keep its API key in the server vault. Do not put the
key in a repository, `server.env`, or a workflow file.

## Configure the server

Store an **OpenRouter** API key in the server vault:

```bash
fabro provider login --provider openrouter --api-key-stdin
```

Add the provider to the server settings:

```toml title="~/.fabro/settings.toml"
[llm.providers.openrouter]
display_name = "OpenRouter"
adapter = "openai_compatible"
base_url = "https://openrouter.ai/api/v1"
enabled = true

[llm.providers.openrouter.auth]
credentials = ["vault:OPENROUTER_API_KEY"]
```

Restart Fabro after editing its settings.

On Fabro `0.316.0-nightly.0`, adding this provider makes built-in catalog models
available through OpenRouter. Do **not** redeclare `claude-sonnet-5` or
`gemini-3.1-pro-preview` as custom OpenRouter models: doing so creates duplicate model
selectors and prevents Fabro from starting.

Verify the route and credentials before using it in a workflow:

```bash
fabro model test --provider openrouter --model claude-sonnet-5
fabro model test --provider openrouter --model gemini-3.1-pro-preview
```

## Use OpenRouter models in a workflow

Always specify the provider and model on deliberately independent review nodes. This
prevents a workflow default from silently routing a Claude or Gemini-labelled review
through OpenAI.

```dot title="workflow.fabro"
model_stylesheet="
  * { provider: openai; model: gpt-5.6-sol; reasoning_effort: high; }
  #claude_review { provider: openrouter; model: claude-sonnet-5; reasoning_effort: high; }
  #gemini_review { provider: openrouter; model: gemini-3.1-pro-preview; reasoning_effort: high; }
"
```

## Adding an unrecognised model

Only create a custom model record when the model is not already in Fabro’s built-in
catalog. Fabro `0.316.0-nightly.0` validates custom records strictly: provide the
complete catalog shape described in [Settings Configuration](/reference/user-configuration),
including family, limits, feature flags, controls, and costs. Validate that record in
an isolated server before restarting a shared Fabro host.

## Troubleshooting

**Missing Authentication header** — confirm that `OPENROUTER_API_KEY` is an OpenRouter
key, not a key from a similarly named service. Re-run `fabro provider login` with the
correct key, then repeat the model probe.

**Gemini direct provider is rate-limited** — an OpenRouter key does not repair the
direct Gemini provider. Route the workflow node explicitly through `openrouter`.

**A review named Gemini or Claude reports an OpenAI error** — inspect the workflow
stylesheet. A label does not select a provider; the node must declare one explicitly.
