Scope and existing states
  • Eve’s existing group placeholder keeps the one-click Request access action, sending feedback, sent confirmation and the option to ask again.
  • If Alice needs to sign in, use the existing sign-in flow and return to this group and person. The email link gives no additional authority.
  • At confirmation, apply current membership and permission rules. If Eve has left the club, she cannot be added. If Alice no longer has permission, she cannot add Eve.
  • Use the existing Adding… disabled-button state and standard error feedback, not new request-specific error screens.
  • Keyboard behaviour: focus the targeted panel heading on arrival. Cancel or Escape closes it and returns focus to the page’s ordinary Add member control. After successful addition, announce success and move focus to Eve’s new member row. Those existing controls remain in the real page; this static preview omits them.
  • The email’s note about replies is true for this example, where Eve is not in Admin. Requests must never remove or contradict existing Admin access.
  • No request statuses, decline action, composer or broader outside-sender reply changes.
  • Based on checked-in group-member and email patterns. Live cloud designs have not been inspected or updated.
