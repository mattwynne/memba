The branding dial

One baseline, dialled per surface

Memba is never hidden — the memba.io domain, the footer line and the sign-in trust mark are present everywhere, asking for no attention. The "dial" is how far Memba moves forward of that baseline on a given surface. The rule of thumb: is this experience about being in one club, or about belonging across clubs? Within → club leads. Across → Memba leads.

The "via" pattern

The club is the sender. Memba is the carrier.

Every club email uses the standard mailing-list dual-brand. The member's eye lands on the club; Memba is named quietly as the postal service. This reduces confusion and spam-flagging rather than causing it — it's exactly what Google Groups, Mailman and Substack do.

A club's own domain is a premium upgrade — never the default

The moment news@theclub.org goes in the From address, Memba inherits that club's DNS and DMARC problems — the exact deliverability pain we avoid. Per-club DKIM setup is offered as a paid upgrade.

Display name Club

Carries the club: Kootenay Mountaineering Club via Memba. For a personal note, the sender's name leads instead: Aoife Brennan via Memba.

Address domain Memba

Always @memba.io — a domain Memba controls, so it can DKIM-sign and DMARC-align cleanly. The local part is the club's slug: wessexchoir@memba.io.

Reply-To Routed

Set to the real human — the sender on a member message, help@memba.io on system mail — so replies land where they should, never on the whole list.

Why not the club's domain? Deliverability

Same name on the login screen, the footer and the URL builds quiet trust. One controlled sending domain keeps every club out of the spam folder.

Layout system

The footer is the constant. The header is the dial.

Every Memba email is still a 560px white card on a warm #ece9e0 field, in the same five regions. v2 makes the split explicit: the footer is the ambient Memba baseline on every email; the header is what moves between club and Memba.

The dial. A club lockup (neutral monogram + name) for club-led mail; the forest Memba mark only when Memba is the speaker, as on the rejection notice.

Email-safe rules

Built to survive any client

Unchanged from v1 — clarity and compatibility over visual complexity. These hold the look together in Gmail, Apple Mail, Outlook and the rest, and degrade gracefully when CSS is stripped.

Type

  • Inter via web font, with -apple-system, Segoe UI, system-ui, sans-serif fallback so stripped clients still look intentional.
  • One family, weight for hierarchy: 600 headlines, 400/500 body.
  • Body 15px / line-height 1.55; never below 13px.
  • JetBrains Mono only for the raw sign-in URL.

Colour

forest
club mark
trust
field
info
  • Forest #1f4842 is Memba's only brand colour — used for actions and the Memba marks.
  • The club mark is a neutral ink tile (#15201c), deliberately not forest, so club ≠ Memba at a glance.
  • Hex values inlined; no var() in email.

Spacing & width

  • 560px card; full-width on screens under 600px (radius drops to 0, gutters tighten to 22px).
  • 28px horizontal gutter on desktop. 4px spacing scale throughout.
  • Single column only — never two-column inside an email.

Buttons

Sign in
  • "Bulletproof" build: a <table> cell with bgcolor + an <a>, plus a VML roundrect for Outlook desktop.
  • Flat forest, 8px radius. No gradient, no shadow.
  • Goes full-width on mobile for an easy tap target.

Fallback links

https://memba.io/signin?t=…
  • The sign-in link is always printed as raw, tappable text below the button — for clients that block or mangle buttons.
  • Mono, word-break:break-all so long tokens wrap instead of overflowing.
  • Every link is also a plain <a href>, never JS-driven.

Dark mode & accessibility

  • Light-only declared via color-scheme meta + tags, so clients don't auto-invert and break the forest button.
  • Colours stay legible if a client inverts anyway — no pure white-on-pure-black flips.
  • Forest on off-white clears WCAG AA. Real text, not images. Hidden preheader sets the inbox preview line.
Both marks (the forest Memba check and the neutral club monogram) render as inline SVG in most modern clients; for Outlook and older webmail, swap each for a hosted 2× PNG with descriptive alt text. Everything else is table + inline CSS that needs no fallback.
